# Memory Hub Actionable Dashboard Spec

> 작성일: 2026-08-02 / 상태: 승인됨

## 문제

Memory Hub에는 검색·이벤트·검색 효용 데이터가 이미 있지만 핵심 행동으로 연결되지 않는다.

- Overview 상단 검색은 결과 탐색을 제공하지 않는다.
- Progressive Retrieval Disclosure 결과 클릭은 넓은 화면에서는 우측 패널만 바꾸고,
  1100px 이하에서는 상세가 결과 목록 아래로 밀려 클릭이 무반응처럼 보인다.
- 최근 질문과 어떤 메모리가 답변에 실제로 쓰였는지가 Overview에 없어, 저장량 중심 숫자만으로는
  메모리 시스템의 가치를 판단하기 어렵다.
- Global Store와 프로젝트 로컬 저장소의 차이가 커도 현재 범위가 충분히 강조되지 않아 빈 화면으로
  오인하기 쉽다.

## 목표

Memory Hub를 저장 현황판에서 **검색하고, 근거를 확인하고, 최근 효용을 판단하는 작업 화면**으로
바꾼다.

## 요구사항

- R1. Overview 상단 검색은 실제 메모리 검색을 실행하고 검색 결과 화면으로 이동한다.
- R2. 검색 결과 클릭 시 현재 뷰포트 안에서 상세가 명확히 열린다. 상세에는 전체 안전 미리보기,
  이벤트 유형·시각·세션, 전후 맥락, 관련 원본, 랭킹 이유가 포함된다.
- R3. 세션 정보가 있는 검색 결과는 해당 세션과 이벤트 위치로 이동할 수 있다.
- R4. 1100px 이하에서도 상세가 결과 목록 아래에 숨지 않는다. 드로어/모달과 포커스 이동으로
  선택 결과를 즉시 확인할 수 있다.
- R5. Overview에 최근 질문을 표시하고, 질문 또는 세션을 클릭해 근거를 탐색할 수 있다.
- R6. Overview에 최근 메모리 효용을 `질문 → 선택된 메모리 → 답변 재사용/유용성` 형태로 표시한다.
- R7. Overview에 가장 유용했던 메모리와 검색 품질 공백(미선택/미평가)을 간결하게 표시한다.
- R8. 로딩·빈 상태·부분 API 실패가 다른 Overview 정보를 가리지 않는다.
- R9. 프로젝트 범위를 눈에 띄게 유지하고 Global Store가 비었을 때 프로젝트 선택을 명확히 유도한다.

## 비목표

- 새 메모리 수집 파이프라인 또는 저장 스키마 추가
- 검색 랭킹 알고리즘 변경
- 원문 transcript 전체를 기본 노출
- 별도 프런트엔드 프레임워크 도입
