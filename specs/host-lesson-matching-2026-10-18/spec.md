# Host 경로 교훈 매칭 개선

상태: 실데이터 평가 + Codex(gpt-6-astra/high)·Claude(claude-fable-5-1/high) 리뷰 반영, **설계 확정 전** · 기준: CML 2.4.12

## 문제

Saycode/Happy 세션(`CLAUDE_MEMORY_LESSON_OWNER=host`)에서는 매 턴 Happy가
`LessonHostService.recall`(src/services/lesson-host-service.ts:133)을 사용자 메시지
원문으로 호출하고, 선택된 교훈을 턴 앞에 붙인다. 선택은 어휘 채점
`scoreLessonEvidence`(src/adapters/claude/hooks/prompt-injection-policy.ts)만 쓴다.
임베딩 보조 경로(src/extensions/mcp/hybrid-lesson-ranking.ts)는 합성 fixture
보정을 통과하지 못해 꺼져 있다.

## 평가 (로컬 전용, 원문은 저장소에 두지 않음)

- Desktop 저장소의 실제 요청 240개를 시간 기준으로 보정 120 / 검증 120으로 나눴다.
  교훈은 recall_enabled 354개.
- 후보 = e5-small 임베딩 상위 6 ∪ 현재 어휘 선택.
- LLM이 "이 요청을 처리하면 trigger 상황에 놓여 단계가 작업을 바꾸는가"를 기준으로
  라벨링했다. host가 붙인 교훈 블록이 섞인 13개는 블록을 제거한 뒤 다시 라벨링했다.
- **시점 보정**: 정답 쌍 52개 중 11개가 요청보다 나중에 생긴 교훈이었다(그 대화에서
  만들어진 교훈). 이를 빼면 적용할 교훈이 있는 요청은 31/240(13%), 정답 쌍은 41개다.

시점 보정 후 결과. 단위를 분리해 적는다: 요청 적중 = 적용 교훈이 있는 요청 중 하나라도
맞춘 비율, 교훈 재현율 = 정답 쌍 기준, any-wrong = 틀린 교훈이 하나라도 들어간 요청.

| 방식 | 결과 |
|---|---|
| 현재 어휘 매칭 | 요청 적중 0/31. 교훈 정밀도 0/6, 음성 요청 오주입 4/209(당시 없던 교훈을 고른 3건 제외) |
| 어휘 게이트 완화(식별자 veto 제거, 절 단위 금지어, 겹침 기준 완화) | 요청 적중 0.23~0.38, 교훈 정밀도 0.02~0.08, 음성 오주입 9~58% |
| 임베딩 점수·격차·z-score 임계 | 맞음/틀림 분리 AUC 0.2~0.9로 split 간 뒤집힘. 쓸 수 있는 임계 없음 |
| 교훈별 가상 요청 예시와 비교 | 후보 적중이 오히려 하락 |
| 임베딩 후보(교훈 전문) | 요청 적중 @1 0.32 · @3 0.68 · @5 0.94 / 교훈 재현율 @5 0.93 |

해석: 임베딩은 **후보 생성**에 쓸 수 있지만, **적용 여부 판정(기권 포함)**에는 어휘·임베딩
어느 쪽도 쓸 수 없다.

수치 사용 시 주의(2차 리뷰에서 확인):
- 후보 풀이 top6 ∪ 어휘이고 어휘 정답이 0이므로 @6은 구조적으로 1.00이다. @5 0.94는
  검색 성능이 아니라 "정답 41개 중 3개가 6위"라는 뜻이다. 인용할 값은 검증셋 11/13
  (Wilson 95% 0.58~0.96)뿐이다.
- 평가 파이프라인 결함: 블록을 제거했다는 13개 프롬프트에 footer가 남은 채로 임베딩
  후보를 계산했다. 동일 프롬프트 1쌍도 남았다. 완화 실험의 "base"는 운영 어휘 채점보다
  느슨한 재구현이라, "어휘 게이트 완화" 행은 운영 대비 수치가 아니다.
- 보정 후 정답 41쌍 중 4쌍은 교훈 생성 8시간 이내다(같은 세션에서 막 만든 교훈의 자기 매칭).
- 양성의 독립성이 낮다. 28개 교훈이 41쌍을 만들고, 반복·유사 요청을 빼면 독립 양성은 약 27개다.
- 허브 교훈: 240개 요청의 top5에 서로 다른 교훈 253개가 등장한다. 한 교훈은 50회 등장한다.
- 기저율: top5 후보 1,194개 중 정답은 38개다. 판정기의 후보당 오수락률이 2%이면 정밀도는
  약 0.6, 5%이면 약 0.35다. 정밀도 0.9에는 오수락률 0.3~0.4% 이하가 필요하다.

## 리뷰 반영 결정

반영한 것:
1. 지표 단위를 분리한다(요청 적중 / 교훈 정밀도·재현율 / 음성 FPR / any-wrong).
2. 후보 풀 편향을 인정한다. 다음 평가에서는 일부 요청을 전체 카탈로그로 라벨링하고,
   풀 밖 표본도 판정한다.
3. 시점 누수를 제거한다(위 보정). 리뷰가 제기한 "당시 존재·권한·revision 재현" 요구를
   평가 파이프라인 요건으로 둔다.
4. **API 계약**: 현재 recall은 선택(최대 3)을 trace로 남기고, ACK에서 같은 ID·revision을
   정확히 요구한다(lesson-host-service.ts:184). 그래서 "top-5를 넘기고 Happy가 일부를
   고르는" 방식은 바로 끼울 수 없다. `candidates → 최종 selected(CML 재검증) → delivered`
   3단계로 분리한다.
5. **지연 예산**: CML 900ms, Happy 전체 1,000ms(lessonTurnHost.ts:33)를 넘기는 동기 판정은
   하지 않는다. shadow로 먼저 측정한다. 늦게 끝난 판정은 다음 턴에 자동 주입하지 않는다.
6. **판정 입력**: name+trigger만으로 충분한지 검증한다. 적용·제외 조건과 scope를 판정 입력
   후보로 두되, reference 권한(lesson-host-service.ts:375)에서 받을 수 없는 필드를 판정
   때문에 노출하지 않는다.
7. **판정기 안전**: 도구 없는 판정기를 쓴다. 출력은 후보 ID allowlist와 개수 상한으로 검증하고,
   범위 밖 ID나 잘못된 JSON은 기권으로 처리한다. 교훈·요청 텍스트는 비신뢰 데이터로 분리한다.
8. **캐시**: 임베딩은 교훈 revision 단위로 캐시한다. 판정 캐시는 요청·actor·권한 세대·후보
   revision·모델/프롬프트 버전을 키로 쓴다.
9. **롤아웃**: shadow → opt-in → 확대. 대조군은 턴이 아니라 세션 단위로 둔다.
10. 제안 2(판정 없이 상위 3개를 상시 노출)는 기각한다. 교훈 정밀도가 약 4%다.

2차 리뷰(claude-fable-5-1)로 추가·수정한 것:
11. **기저율 우선(P0).** 단계 3의 1차 지표를 "후보당 오수락률"로 바꾼다. 판정기 실험 전에
    도달 가능한 정밀도 상한을 계산하고, 판정기 앞에서 오답 후보부터 줄인다. 순서는
    (a) 현재 세션에서 만든 교훈 제외, (b) 허브 교훈 정리(recall 비활성 등),
    (c) 소수 runbook에 명시적 적용 조건을 붙이는 것이다.
    (a)는 `lesson.sourceSessionIds`에 `binding.sessionId`가 있으면 host recall에서 뺀다.
    host가 승인한 교훈의 source 세션은 binding과 같은 네임스페이스다(lesson-host-service.ts:249).
12. **개인정보를 요건으로 승격(P0).** 1차 결정의 "보류"는 근거가 틀렸다. managed 실행에는
    교훈 호스트가 없다(happy claudeRemote.ts:170, lessonSessionHost.ts:298). recall이 켜지는
    비managed 실행은 provider로 직접 간다. 따라서 판정기 gateway는 새 수신자다.
    판정 입력에는 기존 리뷰 gateway와 같은 redaction과 private 거부를 적용한다. 세션별 opt-in으로
    두고, 세션의 provider와 다른 vendor로 판정을 보내지 않는다.
13. **API(P1).** recall `limit`과 ack 배열은 `.max(3)`이다(lesson-host-service.ts:134, :185).
    후보는 별도 메서드(상한 5~6)로 내고, `LESSON_HOST_CAPABILITIES`(:18)에 플래그를 둬
    구버전 조합은 기존 recall로 떨어지게 한다. selected·ack 계약(3개)은 그대로 둔다.
14. **콜드 스타트·폴백(P1).** 임베딩 워밍은 어휘 결과가 빈 recall에서야 시작하고, 그동안
    빈 결과를 돌려준다(hybrid-lesson-ranking.ts:59). 스토어를 열 때 워밍한다. Embedder가
    폴백 모델로 바뀌면(embedder.ts:113) 후보 생성을 끈다. shadow에서 cold-turn 비율을 잰다.
15. **요청 맥락(P2).** 240개 중 77개가 40자 미만이다. 직전 사용자 메시지와 직전 턴에 관측된
    명령을 요청 쪽 입력으로 쓰는 실험을 하고, 판정 캐시 키에 넣는다.
16. **shadow 기록(P2).** recall trace는 의도적으로 `query_text`를 NULL로 쓴다. shadow도 요청
    해시·후보 ID·판정 결과만 기록한다.

반영하지 않거나 보류한 것:
- 사람의 독립 판정은 필요하다고 보지만 이 작업에서 대신할 수 없다. 사용자 작업으로 남긴다.

## 단계 1·후보 축소 측정 결과 (2026-10-18)

`scripts/evaluate-host-lesson-matching.ts`로 같은 라벨을 재현 가능하게 다시 집계했다.
조건은 다음과 같다.
- 저장소는 읽기 전용으로 열었다.
- 정규화(이 브랜치의 footer 수정 포함)를 후보 생성 전에 했다. 블록 흔적이 남은 프롬프트는 0건이다.
- 시점 필터를 후보와 정답 양쪽에 적용했다.
- 라벨 229개가 결합됐다. 보정셋 양성 18 / 음성 100, 검증셋 양성 10 / 음성 101이다.

| (검증셋) | 결과 |
|---|---|
| 현재 어휘 | 요청 적중 1/10, 교훈 정밀도 1/4, 음성 오주입 2/101 |
| 임베딩 top5 후보, 축소 없음 | 정답 후보 10 / 오답 후보 531, 요청 적중 8/10. 오수락률 0.5%·1%·2%에서 도달 가능 정밀도 0.79·0.65·0.49 |
| 같은 세션 교훈 제외 | 효과 없음. 시점 필터 후 해당 후보가 남지 않는다 |
| 허브 제외 (보정셋 top5 등장 15% / 5% / 3%) | 허브 1 / 28 / 56개. 검증셋 도달 정밀도(0.5%)는 0.81 / 0.81 / 0.79에 그친다. 3%에서는 요청 적중이 6/10으로 떨어진다 |
| top3 후보 | 정답 7 / 오답 319, 요청 적중 6/10, 0.5%에서 0.81 |

결론: 판정기 앞 후보 축소로는 기저율 문제가 풀리지 않는다. 판정기가 오답 후보의 0.5%만
받아들여도 검증셋 정밀도 상한은 약 0.8이다. 따라서 "임베딩 후보 + 소형 LLM 판정"은
현재 교훈 목록에서 단계 3의 출시 게이트(정밀도 95% 하한 ≥0.9)에 닿기 어렵다.
단계 3 판정기 실험에 들어가기 전에 둘 중 하나를 정해야 한다.
- (a) 매 턴 자동 주입 대신 행동 시점(명령·오류 관측) 매칭이나 사용자 호출형으로 문제를 바꾼다.
- (b) 정밀도 목표를 낮추고 reference(이름+trigger) 전달로 비용을 줄인다.

## 단계 계획과 수용 기준

| 단계 | 작업 | 수용 기준 |
|---|---|---|
| 1 평가 재현성 | 정제→후보→라벨→집계를 한 스크립트로 고정한다. 블록 제거는 후보 생성 전에 하고, 시점 필터는 어휘·임베딩 출력에도 적용한다. 중복을 제거하고, 24시간 이내 쌍은 분리 보고한다. 데이터는 로컬 경로 인자로만 받는다 | 같은 입력이면 같은 결과. 지표 단위 명시. 미래 교훈 0건. 블록 마커가 남은 프롬프트 0건 |
| 2 정답 보강 | 일부 요청은 전체 카탈로그로 라벨링하고 사람이 판정. 새 시간 구간의 봉인 표본을 만든다 | 양성 요청 100 이상(서로 다른 교훈 50 이상), 음성 300 이상. `맥락 부족` 별도 표기 |
| 3 오프라인 판정 실험 | 먼저 판정기 앞 후보 축소(자기 세션 교훈 제외, 허브 정리, 명시적 조건). 그다음 현재 어휘 / 명시적 조건 / 임베딩 후보+소형 LLM 판정을 비교 | 1차: 후보당 오수락률과 그 기저율에서 도달 가능한 정밀도 상한을 먼저 보고. 출시 게이트: 봉인셋 교훈 정밀도 95% 하한 ≥0.9, 음성 FPR 95% 상한 ≤1%, 요청 적중 ≥0.8. 기존 식별자 양성 회귀 0 |
| 4 shadow | host 경로에서 후보·판정을 기록만 한다(주입 없음, 원문 저장 없음). 계약·취소·권한 철회·revision 변경·capability 협상을 확인 | 오권한·다른 턴 전달·허위 ACK 0. foreground 예산 유지. 예산 내 완료율과 cold-turn 비율 측정 |
| 5 opt-in | 세션 단위 대조군으로 전달 | 잘못된 절차 적용·재작업이 대조군 대비 증가 없음 |

## 비목표

- 매칭 수·노출 수 증가를 성공 지표로 삼지 않는다.
- 평가 원문을 커밋하지 않는다.
- 단계 3을 통과하기 전에는 기본 동작을 바꾸지 않는다.
