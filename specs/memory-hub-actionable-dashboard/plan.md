# Memory Hub Actionable Dashboard Plan

> 작성일: 2026-08-02 / 상태: 완료
> 근거: [spec.md](./spec.md)

## 아키텍처 영향

| 항목 | 내용 |
|------|------|
| 변경 계층 | `src/apps/dashboard/` 정적 HTML/CSS/JS |
| 서버 API | 기존 `/api/search/disclosure`, `/api/events`, `/api/stats/usefulness-history`, `/api/stats/helpfulness` 재사용 |
| 새 외부 의존성 | 없음 |
| 저장 스키마 | 변경 없음 |
| 공개 API | 변경 없음 |

기존 데이터 계약만으로 목표를 달성한다. Overview 전용 집계 API는 여러 기존 호출로 성능 문제가
확인될 때만 별도 작업으로 제안한다.

## Phase 1: 검색 행동 복구 — Done

- Overview 검색을 Progressive Retrieval Disclosure 검색으로 연결한다.
- 검색 결과 선택 상태를 명시하고, 상세 로딩·성공·실패 상태를 접근 가능한 드로어로 표현한다.
- 결과 상세에서 세션, 관련 원본, 전후 맥락으로 이동할 수 있게 한다.

검증: 검색 실행, 결과 클릭, API 실패, 키보드 선택, 세션 이동 테스트.

## Phase 2: 반응형 상세 UX — Done

- 넓은 화면은 결과+상세 병렬 탐색을 유지한다.
- 1100px 이하에서는 상세 드로어를 고정 오버레이로 띄우고 닫기·ESC·포커스 이동을 제공한다.
- 중복 액션과 긴 원문으로 인한 무한 높이를 제거한다.

검증: CSS 계약 테스트와 실제 브라우저 1100px 이하 확인.

## Phase 3: 행동 가능한 Overview — Done

- 최근 질문 카드: 최근 user_prompt, 시각, 세션 이동.
- 최근 메모리 효용 카드: 질문, 주입 메모리 수, 답변 재사용 여부, 최고 유용성 점수.
- 유용한 메모리 카드: 요약, 유용성, 사용 횟수, 상세 열기.
- 검색 공백: 최근 질문 중 미선택·미평가 건수를 짧은 진단으로 표시.

검증: 정상·빈 데이터·부분 실패·HTML escaping 테스트.

## Phase 4: 범위와 최종 검증 — Done

- Global Store 빈 상태와 프로젝트 선택 안내를 강화한다.
- 선택된 프로젝트 범위와 데이터 최신 시점을 Overview 활동 카드에 표시한다.
- 전체 검증과 실제 대시보드 점검을 수행한다.

## 기각한 대안

- 새 대시보드 집계 테이블: 기존 데이터와 진실 원천이 중복된다.
- 검색 결과 클릭 시 새 페이지 이동: 결과 간 비교가 느려지고 기존 disclosure 흐름을 버리게 된다.
- Overview에 모든 진단 지표 노출: 정보량은 늘지만 사용자가 무엇을 해야 하는지 더 불명확해진다.
